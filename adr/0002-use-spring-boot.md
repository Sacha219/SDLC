# Использование Spring Boot для серверной части

## Контекст и постановка задачи
Приложению необходима серверная часть, которая будет обрабатывать HTTP-запросы, выполнять бизнес-логику (проверка свободных мест, роли пользователей) и работать с базой данных PostgreSQL. На каком стеке реализовать Backend?

## Драйверы решения
* **Безопасность:** Встроенная защита (Spring Security) для разделения ролей Администратора и Ученика.
* **Интеграция с БД:** Удобная работа с PostgreSQL через JPA.
* **Опыт команды:** Наличие опыта разработки на Java.

## Рассмотренные варианты
* Java + Spring Boot
* Node.js + Express
* Python + Django

## Итог решения
Выбран вариант **«Java + Spring Boot»**, потому что фреймворк предоставляет готовые модули безопасности, работы с БД и веб-сервера.

### Последствия
* **Хорошо:** строгая типизация снижает количество ошибок, встроенный Spring Security упрощает настройку JWT.
* **Плохо:** большее потребление оперативной памяти по сравнению с Node.js.

### Подтверждение
Проверка наличия зависимостей `spring-boot-starter-web` и `spring-boot-starter-security` в `pom.xml`.

## Плюсы и минусы вариантов
### Java + Spring Boot
* **Хорошо:** встроенные модули безопасности и БД.
* **Плохо:** высокое потребление памяти.

### Node.js + Express
* **Хорошо:** низкое потребление памяти.
* **Плохо:** нет строгой типизации, сложнее поддерживать большой проект.

### Python + Django
* **Хорошо:** быстрая разработка.
* **Плохо:** ниже производительность при нагрузках.

## Дополнительная информация
Адресует требования SRS: REQ-FUNC-001 (авторизация), REQ-SEC-002 (разграничение прав). Связано с ADR-001 (PostgreSQL) и ADR-003 (React).
