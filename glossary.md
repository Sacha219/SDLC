# Глоссарий проекта «RhythmSpace»

**Проект:** веб-приложение для школы танцев «RhythmSpace»
**Версия:** 1.0
**Автор:** Лукашевич А.Д.
**Дата:** 22.11.2026
**Связанные документы:** [SRS](srs/srs1.1.md), [SDD](sdd/sdd.md), [use-case.md](use-case.md)

Глоссарий фиксирует единое значение терминов, которые встречаются в требованиях, проектной документации и диаграммах. Если термин в документах употреблён иначе, приоритет имеет определение из этой таблицы.

## 1. Предметная область

| Термин | Определение | Где используется |
|---|---|---|
| Школа танцев | Организация-заказчик, которая проводит платные занятия по танцевальным направлениям в нескольких филиалах | SRS 2.1 |
| Филиал (студия) | Отдельная площадка школы с собственным адресом и расписанием занятий | REQ-FUNC-005, таблица `branches` |
| Направление | Танцевальный стиль занятия (например, хип-хоп, бальные танцы); признак для поиска и фильтрации | REQ-FUNC-006, UC-12 |
| Преподаватель (тренер) | Сотрудник школы, который ведёт занятия; в системе имеет карточку с биографией и фотографией | REQ-FUNC-008, UC-13 |
| Занятие | Конкретное событие в расписании: филиал, преподаватель, направление, время начала, вместимость | таблица `lessons` |
| Групповое занятие | Занятие, на которое могут записаться несколько учеников, пока не исчерпана вместимость | REQ-FUNC-002, UC-03 |
| Индивидуальное занятие | Занятие ученика с выбранным тренером, доступное при наличии у тренера свободного времени | REQ-FUNC-009, UC-05 |
| Расписание | Упорядоченный по времени список предстоящих занятий выбранного филиала | REQ-FUNC-002, UC-02 |
| Вместимость (`max_students`) | Наибольшее число учеников, которое может быть записано на групповое занятие | таблица `lessons` |
| Число броней (`booked_count`) | Текущее число активных записей на занятие | таблица `lessons`, SDD 2.2.10 |
| Свободные места | Разность между вместимостью и числом броней; показывается на карточке занятия | REQ-FUNC-007, UC-04 |
| Запись (бронь) | Факт закрепления места на занятии за конкретным учеником | таблица `bookings`, UC-03, UC-05 |
| Статус записи | Состояние записи: «Активна», «Отменена учеником», «Посещена» | SDD 2.2.11 |
| Отмена записи | Действие ученика, после которого запись получает статус «Отменена учеником», а место возвращается в группу | REQ-FUNC-003, UC-06 |
| Овербукинг | Ситуация, когда на занятие записано больше учеников, чем позволяет вместимость | ADR-0001 |
| Профиль | Личная страница ученика с контактными данными и уровнем подготовки | REQ-FUNC-004, UC-10 |
| Уровень подготовки | Оценка опыта ученика (начальный, средний и т.д.), хранится в поле `users.level` | REQ-FUNC-004 |
| Трекер прогресса | Часть профиля, которая считает посещения и показывает достижения | REQ-FUNC-004, UC-10 |
| Достижение | Отметка о выполненной цели ученика (например, число посещённых занятий) | таблица `achievements` |
| История посещений | Перечень занятий, на которых ученик побывал | REQ-INT-002, UC-09 |
| Чат | Окно обмена текстовыми сообщениями между учеником и администратором в реальном времени | REQ-FUNC-010, UC-08 |

## 2. Роли и участники

| Термин | Определение | Где используется |
|---|---|---|
| Пользователь | Обобщённое имя актёра на диаграмме прецедентов: человек, который работает с приложением через браузер (в роли ученика) | use-case.md, диаграмма прецедентов |
| Ученик | Клиент школы; смотрит расписание, записывается и отменяет запись, ведёт профиль, пишет в чат | SRS 2.4 |
| Администратор | Сотрудник школы, который ведёт расписание и записи и отвечает в чате; в модели ЛР №5 отдельным актёром не показан | SRS 2.4 |
| Актёр | Роль человека или внешней системы по отношению к проектируемой системе | UML |
| База данных | Внешний по отношению к приложению узел хранения (PostgreSQL), с которым взаимодействуют прецеденты UC-02 и UC-04 | use-case.md |

## 3. Технические термины

| Термин | Определение | Где используется |
|---|---|---|
| SPA | Single Page Application: одностраничное клиентское приложение на React | SDD 2.2.2 |
| REST API | Интерфейс клиент-серверного обмена в стиле REST, формат данных JSON | REQ-INT-006 |
| JWT-токен | Подписанный токен, который сервер выдаёт после входа; клиент передаёт его в каждом защищённом запросе | UC-07, диаграмма последовательности |
| BCrypt | Алгоритм хеширования паролей; пароли хранятся только в виде хешей | REQ-SEC-001 |
| RBAC | Разграничение прав по ролям (ученик, администратор) | REQ-SEC-002 |
| WebSocket | Постоянное двустороннее соединение браузера и сервера, на котором построен чат | REQ-INT-007 |
| SMTP | Протокол отправки электронной почты; используется для подтверждений записи | REQ-INT-005, ADR-0005 |
| Транзакция | Группа операций с БД, которая выполняется целиком или не выполняется вовсе (ACID) | SDD 2.2.12, ADR-0001 |
| Оптимистичная блокировка | Механизм JPA: перед сохранением сверяется версия записи, при конфликте операция отклоняется | SDD 2.2.12 |
| Race condition | Состояние гонки: два запроса одновременно занимают последнее свободное место | SDD 2.2.12 |
| Entity | Java-класс, отображаемый на таблицу БД | SDD 3.2 |
| Repository | Слой доступа к данным (`JpaRepository`) | SDD 3.2 |
| Service | Слой бизнес-логики (например, `BookingService`) | SDD 3.2 |
| Controller | Слой, принимающий HTTP-запросы (например, `BookingController`) | SDD 3.2 |
| DTO | Data Transfer Object: объект для передачи данных между слоями и клиентом | SDD 2.2.13 |
| MVC | Model-View-Controller: шаблон разделения данных, представления и управления | SDD 2.2.3 |
